Audit des applications Entra ID

Les applications enregistrées et les applications d'entreprise ont souvent plus de droits que les utilisateurs eux-mêmes, avec des secrets qui ne sont jamais renouvelés. Une application compromise ou oubliée donne un accès durable et discret au tenant. Ces 5 contrôles passent en revue les permissions, les secrets, les propriétaires et les applications multi-tenant.

APP-001

Applications avec permissions administrateur excessives

Sévérité critique
Ce qui est vérifié
Repère les applications qui ont reçu, avec le consentement administrateur pour tout le tenant, des permissions à haut risque : lecture ou écriture de tout l'annuaire, gestion des rôles ou des applications.
Valeur attendue
Aucune application avec Directory.ReadWrite.All ou RoleManagement.ReadWrite.Directory accordée au niveau du tenant.

Temps estimé15 à 30 min par application

RéférentielsCIS M365 v3.0 section 4ISO 27001 A.5.15NIS2 Art.21ANSSI Hygiène mesure 9RGPD Art.32.1.bRGPD Art.25

À savoir avant de commencer : Retirer une permission peut casser l'application qui s'en sert. Demandez d'abord à son propriétaire ou à l'éditeur ce dont elle a vraiment besoin, et notez la permission retirée pour pouvoir la rendre.

Corriger dans le portail

  1. Centre d'administration Microsoft Entra > Identité > Applications > Inscriptions d'applications > Toutes les applications.
  2. Ouvrez chaque application citée > Autorisations de l'API : repérez les permissions de type « Application » à haut risque (Directory.ReadWrite.All, RoleManagement.ReadWrite.Directory, Application.ReadWrite.All, AppRoleAssignment.ReadWrite.All, User.ReadWrite.All, GroupMember.ReadWrite.All, Mail.ReadWrite, Files.ReadWrite.All).
  3. Remplacez-les par une permission plus étroite quand c'est possible (par exemple User.Read.All au lieu de User.ReadWrite.All, Sites.Selected au lieu de Files.ReadWrite.All), puis cliquez sur « … » > Révoquer le consentement de l'administrateur et supprimez la permission inutile.
  4. Application inutilisée : supprimez-la (elle reste restaurable 30 jours dans « Applications supprimées »).
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script ne liste plus que les permissions dont l'usage est justifié et documenté.
  • Les applications concernées fonctionnent toujours (demandez une vérification à leur propriétaire).

Documentation Microsoft : learn.microsoft.com/en-us/azure/active-directory/manage-apps/manage-application-permissions · learn.microsoft.com/en-us/security/zero-trust/develop/permissions-require-admin-consent

APP-002

Secrets d'application expirés ou expirant sous 30 jours

Sévérité élevée
Ce qui est vérifié
Les secrets client et les certificats des applications enregistrées doivent être renouvelés avant leur expiration. Un secret expiré bloque l'application ; un secret qui expire bientôt annonce une coupure de service.
Valeur attendue
Aucun secret expiré et aucun secret qui expire dans moins de 30 jours.

Temps estimé10 min par application

RéférentielsCIS M365 v3.0 section 4ISO 27001 A.8.2NIS2 Art.21ANSSI Hygiène mesure 11RGPD Art.32.1.b

À savoir avant de commencer : Un secret expiré ne fonctionne déjà plus : si l'application sert encore, elle est probablement en panne. Créez le nouveau secret et mettez-le dans le service qui l'utilise avant de supprimer l'ancien.

Corriger dans le portail

  1. Centre d'administration Microsoft Entra > Identité > Applications > Inscriptions d'applications > Toutes les applications.
  2. Ouvrez chaque application citée > Certificats et secrets : repérez les secrets et certificats expirés.
  3. Application encore utilisée : « Nouveau secret client » (12 mois au plus), copiez la valeur dans la configuration du service concerné, vérifiez qu'il fonctionne, puis supprimez l'ancien secret.
  4. Application abandonnée : supprimez le secret expiré, ou l'application entière si plus personne ne s'en sert.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script ne liste plus aucun secret expiré.
  • Les applications renouvelées se connectent avec leur nouveau secret (journaux de connexion des principaux de service dans Entra).

Documentation Microsoft : learn.microsoft.com/en-us/azure/active-directory/develop/howto-create-service-principal-portal · learn.microsoft.com/en-us/azure/active-directory/manage-apps/app-management-policies

APP-003

Applications sans propriétaire

Sévérité moyenne
Ce qui est vérifié
Chaque application enregistrée doit avoir au moins un propriétaire identifié, responsable de sa gestion et de son cycle de vie. Sans propriétaire, une application devient orpheline : personne ne la maintient ni ne la supprime.
Valeur attendue
Toutes les applications ont au moins un propriétaire.

Temps estimé5 min par application

RéférentielsCIS M365 v3.0 section 4ISO 27001 A.5.15NIS2 Art.21ANSSI Hygiène mesure 4ANSSI Hygiène mesure 9RGPD Art.32.1.b

À savoir avant de commencer : Choisissez comme propriétaire la personne qui connaît l'usage de l'application, pas seulement un administrateur. Une application que personne ne reconnaît est candidate à la suppression.

Corriger dans le portail

  1. Centre d'administration Microsoft Entra > Identité > Applications > Inscriptions d'applications > Toutes les applications.
  2. Ouvrez chaque application citée > Propriétaires > Ajouter des propriétaires : ajoutez au moins deux personnes (dont une de l'équipe informatique).
  3. Si personne ne reconnaît l'application, vérifiez ses connexions récentes (Applications d'entreprise > l'application > Journaux de connexion) puis supprimez-la.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script ne liste plus d'application sans propriétaire, ou seulement des applications dont la suppression est prévue.

Documentation Microsoft : learn.microsoft.com/en-us/azure/active-directory/develop/howto-add-app-roles-in-apps · learn.microsoft.com/en-us/azure/active-directory/fundamentals/governance-service-overview

APP-004

Applications multi-tenant ayant accès au tenant

Sévérité moyenne
Ce qui est vérifié
Les applications multi-tenant (signInAudience « AzureADMultipleOrgs » ou « AzureADandPersonalMicrosoftAccount ») acceptent des connexions depuis n'importe quel tenant. Leur présence doit être identifiée et justifiée.
Valeur attendue
Applications multi-tenant identifiées, documentées et justifiées.

Temps estimé15 min par application

RéférentielsCIS M365 v3.0 section 4ISO 27001 A.5.15NIS2 Art.21ANSSI Hygiène mesure 3ANSSI Hygiène mesure 9RGPD Art.32.1.bRGPD Art.28

À savoir avant de commencer : Ne restreignez une application à votre seule organisation que si elle ne sert qu'en interne : une application utilisée par des partenaires ou des comptes personnels cesserait de fonctionner pour eux.

Corriger dans le portail

  1. Centre d'administration Microsoft Entra > Identité > Applications > Inscriptions d'applications > Toutes les applications.
  2. Ouvrez chaque application citée > Authentification : la zone « Types de comptes pris en charge » indique qui peut s'y connecter.
  3. Application interne : choisissez « Comptes dans cet annuaire d'organisation uniquement (locataire unique) » et enregistrez.
  4. Application réellement multi-organisation : notez la raison et vérifiez qu'elle ne demande aucune permission à haut risque (voir APP-001).
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Chaque application encore multi-organisation a une raison notée et aucune permission à haut risque.
  • Les utilisateurs internes se connectent toujours aux applications passées en locataire unique.

Documentation Microsoft : learn.microsoft.com/en-us/azure/active-directory/develop/single-and-multi-tenant-apps · learn.microsoft.com/en-us/azure/active-directory/manage-apps/tenant-restrictions

APP-005

Identifiants d'applications non renouvelés depuis plus d'un an

Sévérité élevée
Ce qui est vérifié
Les applications d'entreprise (principaux de service) dont les secrets ou certificats ont été créés il y a plus d'un an sans renouvellement allongent la fenêtre d'exposition en cas de vol de l'identifiant.
Valeur attendue
Tous les identifiants d'applications renouvelés au cours des 12 derniers mois.

Temps estimé15 min par application

RéférentielsCIS M365 v3.0 section 4ISO 27001 A.8.2NIS2 Art.21ANSSI Hygiène mesure 11RGPD Art.32.1.b

À savoir avant de commencer : Certains principaux de service sont créés et gérés par Microsoft (par exemple « P2P Server », utilisé pour le Bureau à distance vers les PC joints à Entra ID) : ne les supprimez pas ; vérifiez seulement que leurs identifiants sont encore utiles.

Corriger dans le portail

  1. Centre d'administration Microsoft Entra > Identité > Applications > Applications d'entreprise > Toutes les applications.
  2. Pour une application SAML : ouvrez-la > Authentification unique > Certificat de signature SAML > créez un nouveau certificat, transmettez-le à l'éditeur, activez-le, puis supprimez l'ancien.
  3. Pour une application inscrite dans votre tenant : Inscriptions d'applications > l'application > Certificats et secrets > créez un nouvel identifiant, mettez-le à jour dans le service, puis supprimez l'ancien.
  4. Fixez une durée de vie d'un an au plus pour les nouveaux secrets, et préférez une identité managée pour les services hébergés dans Azure.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script ne liste plus que des identifiants gérés par Microsoft ou dont le renouvellement est planifié.

Documentation Microsoft : learn.microsoft.com/en-us/azure/active-directory/develop/howto-create-service-principal-portal · learn.microsoft.com/en-us/azure/active-directory/managed-identities-azure-resources/overview
