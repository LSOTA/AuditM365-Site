Audit des appareils Intune

Un appareil non chiffré, jamais mis à jour ou sorti du parc depuis des mois est un point d'entrée et un risque de fuite. Ces 10 contrôles vérifient la gestion des appareils par Microsoft Intune : stratégies et taux de conformité, chiffrement BitLocker et FileVault, versions de système, anneaux Windows Update, bases de sécurité, protection des applications mobiles et Windows Hello for Business.

INT-001

Taux de conformité des appareils Intune

Sévérité élevée
Ce qui est vérifié
Mesure la part des appareils gérés par Intune qui respectent les stratégies de conformité.
Valeur attendue
90 % d'appareils conformes au moins.

Temps estimé1 à 2 h, puis une semaine de suivi

RéférentielsCIS M365 v3.0 section 8ISO 27001 A.8.9NIS2 Art.21ANSSI Hygiène mesure 14ANSSI Hygiène mesure 16RGPD Art.32.1.b

À savoir avant de commencer : Ne passez le réglage « appareils sans stratégie de conformité » à « Non conforme » qu'une fois chaque système utilisé couvert par une stratégie attribuée qui évalue vraiment des appareils. Sinon, les appareils non couverts deviennent non conformes d'un coup, et une stratégie d'accès conditionnel qui exige un appareil conforme les bloque.

Corriger dans le portail

  1. Centre d'administration Intune > Appareils > Conformité > Stratégies : ouvrez chaque stratégie > Propriétés > Attributions. Une stratégie sans attribution n'évalue aucun appareil : attribuez-la à « Tous les appareils » ou au groupe des postes concernés.
  2. Dans la même stratégie, « État de l'appareil » doit montrer des appareils évalués (conformes ou non). Zéro appareil évalué : l'attribution ne vise pas les bons appareils.
  3. Appareils > Tous les appareils, filtre Conformité = Non conforme : ouvrez un appareil > Conformité de l'appareil pour voir le paramètre en cause (chiffrement, version du système, mot de passe…), et corrigez par lot.
  4. Quand tous les systèmes sont couverts : Appareils > Conformité > Paramètres de stratégie de conformité > « Marquer les appareils sans stratégie de conformité attribuée comme » = Non conforme.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Chaque système du parc a une stratégie avec au moins une attribution et des appareils évalués.
  • Relancez un audit : le taux de conformité réelle remonte, et le texte ne parle plus d'appareils « déclarés conformes par défaut ».

Documentation Microsoft : learn.microsoft.com/en-us/mem/intune/protect/device-compliance-get-started

INT-002

Chiffrement des appareils (BitLocker / FileVault)

Sévérité élevée
Ce qui est vérifié
Tous les appareils gérés doivent avoir le disque chiffré : BitLocker sous Windows, FileVault sous macOS.
Valeur attendue
100 % des appareils chiffrés.

Temps estimé2 à 4 h, puis déploiement progressif

RéférentielsCIS M365 v3.0 section 8ISO 27001 A.8.7NIS2 Art.21ANSSI Hygiène mesure 31RGPD Art.32.1.a

À savoir avant de commencer : Vérifiez d'abord que les clés de récupération BitLocker sont bien sauvegardées dans Entra ID : un poste chiffré dont la clé est perdue ne se récupère pas. Testez sur un groupe pilote : les vieux PC sans TPM 2.0 ne se chiffrent pas sans intervention de l'utilisateur.

Corriger dans le portail

  1. Centre d'administration Intune > Sécurité des points de terminaison > Chiffrement de disque > Créer une stratégie > Windows > BitLocker.
  2. Réglages conseillés : exiger le chiffrement de l'appareil ; autoriser le chiffrement par les utilisateurs standard (chiffrement silencieux sur les postes joints à Entra ID) ; enregistrer les informations de récupération dans Entra ID avant d'activer BitLocker ; chiffrement XTS-AES 256 bits.
  3. Attribuez d'abord à un groupe pilote, puis à tous les postes Windows. Pour les Mac : même chemin > macOS > FileVault.
  4. Ajoutez « Exiger BitLocker » dans la stratégie de conformité Windows (Appareils > Conformité), pour que les postes non chiffrés apparaissent non conformes.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le nombre d'appareils non chiffrés baisse à chaque synchronisation des postes du groupe ciblé.
  • Entra ID > Appareils > un poste chiffré > Clés de récupération BitLocker : la clé y figure.

Documentation Microsoft : learn.microsoft.com/en-us/mem/intune/protect/encrypt-devices · learn.microsoft.com/en-us/mem/intune/protect/encrypt-devices-filevault

INT-003

Politiques de conformité Intune par système

Sévérité élevée
Ce qui est vérifié
Au moins une stratégie de conformité active doit exister pour chaque système principal : Windows, iOS et Android.
Valeur attendue
Au moins une stratégie active par système (Windows, iOS, Android).

Temps estimé30 min par système

RéférentielsCIS M365 v3.0 section 8ISO 27001 A.8.9NIS2 Art.21ANSSI Hygiène mesure 14ANSSI Hygiène mesure 16ANSSI Hygiène mesure 33RGPD Art.32.1.b

À savoir avant de commencer : Si une stratégie d'accès conditionnel exige un appareil conforme sur mobile, les téléphones non inscrits dans Intune seront bloqués. Pour les téléphones personnels, préférez la protection des applications (INT-007) à l'inscription obligatoire.

Corriger dans le portail

  1. Centre d'administration Intune > Appareils > Conformité > Créer une stratégie > iOS/iPadOS : version minimale du système (une version encore mise à jour par Apple), code secret exigé, appareils jailbreakés = Bloquer.
  2. Même chemin > Android Enterprise (profil professionnel personnel et appareils entièrement gérés) : appareils rootés = Bloquer, niveau de correctif de sécurité minimal, mot de passe exigé.
  3. Actions en cas de non-conformité : marquer non conforme immédiatement, et envoyer un e-mail à l'utilisateur au bout d'un jour.
  4. Attribuez chaque stratégie à « Tous les utilisateurs » (ou au groupe qui inscrit des mobiles).
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Chaque système présent dans le parc a au moins une stratégie de conformité attribuée.
  • Dans chaque nouvelle stratégie, « État de l'appareil » montre des appareils évalués après quelques heures.

Documentation Microsoft : learn.microsoft.com/en-us/mem/intune/protect/create-compliance-policy

INT-004

Appareils inactifs depuis plus de 90 jours

Sévérité moyenne
Ce qui est vérifié
Aucun appareil ne doit rester plus de 90 jours sans se synchroniser avec Intune : c'est le signe d'un appareil abandonné, perdu ou compromis.
Valeur attendue
Aucun appareil inactif depuis plus de 90 jours.

Temps estimé30 min, puis automatique

RéférentielsCIS M365 v3.0 section 8ISO 27001 A.8.9NIS2 Art.21ANSSI Hygiène mesure 4RGPD Art.32.1.b

À savoir avant de commencer : Supprimer un appareil d'Intune n'efface pas son contenu. S'il sert encore, il se réinscrit à la prochaine connexion (postes joints à Entra ID avec inscription automatique). Les clés BitLocker et l'inscription Autopilot ne sont pas touchées.

Corriger dans le portail

  1. Centre d'administration Intune > Appareils > Tous les appareils : triez par « Dernier archivage » pour repérer les appareils muets depuis plus de 90 jours.
  2. Demandez aux utilisateurs concernés si l'appareil existe encore (perdu, remplacé, rendu).
  3. Appareils > Règles de nettoyage des appareils : créez une règle par système qui supprime les appareils inactifs depuis 90 jours. Le ménage se fait ensuite seul.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script ne liste plus d'appareil muet depuis plus de 90 jours.
  • La règle de nettoyage apparaît dans Appareils > Règles de nettoyage des appareils.

Documentation Microsoft : learn.microsoft.com/en-us/mem/intune/remote-actions/devices-wipe

INT-005

Appareils avec une version de système obsolète

Sévérité moyenne
Ce qui est vérifié
Aucun appareil ne doit fonctionner avec une version de système qui n'est plus prise en charge : Windows antérieur à 10.0.19041, iOS antérieur à 16, Android antérieur à 12.
Valeur attendue
Aucun appareil avec une version de système obsolète.

Temps estimé15 min, puis suivi par appareil

RéférentielsCIS M365 v3.0 section 8ISO 27001 A.8.7NIS2 Art.21ANSSI Hygiène mesure 34ANSSI Hygiène mesure 35RGPD Art.32.1.b

À savoir avant de commencer : Exiger une version minimale rend non conformes, d'un coup, tous les appareils en dessous. Si l'accès conditionnel exige un appareil conforme, leurs utilisateurs perdent l'accès : prévenez-les et prévoyez la mise à jour ou le remplacement d'abord.

Corriger dans le portail

  1. Contactez les utilisateurs des appareils cités : mise à jour du système si l'appareil le permet, sinon remplacement (Windows 10 n'a plus de correctifs gratuits depuis octobre 2025).
  2. Centre d'administration Intune > Appareils > Conformité > la stratégie Windows > Propriétés des paramètres > Propriétés de l'appareil > Version minimale du système d'exploitation (par exemple 10.0.19045 pour Windows 10 22H2, ou une version de Windows 11).
  3. Même réglage dans les stratégies iOS/iPadOS et Android.
  4. Mises à jour Windows : anneaux de mise à jour et mises à jour de fonctionnalités (voir INT-009).
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script ne liste plus d'appareil, ou seulement des appareils dont le remplacement est planifié.
  • La stratégie de conformité de chaque système contient une version minimale.

Documentation Microsoft : learn.microsoft.com/en-us/mem/intune/protect/create-compliance-policy · learn.microsoft.com/en-us/windows/deployment/update/waas-overview

INT-006

Applications requises déployées par Intune

Sévérité faible
Ce qui est vérifié
Des déploiements obligatoires doivent être configurés dans Intune pour les applications de sécurité (EDR, VPN, application d'authentification).
Valeur attendue
Déploiements d'applications obligatoires configurés.

Temps estimé15 min par application en échec

RéférentielsCIS M365 v3.0 section 9ISO 27001 A.8.9NIS2 Art.21ANSSI Hygiène mesure 16RGPD Art.32.1.b

À savoir avant de commencer : Un échec d'installation peut venir de l'appareil (place disque, redémarrage en attente, version déjà installée à la main) plutôt que de l'application. Regardez le code d'erreur avant de republier un paquet.

Corriger dans le portail

  1. Centre d'administration Intune > Applications > Toutes les applications : ouvrez une application citée par le script > État d'installation de l'appareil, filtre « Échec ».
  2. Le code d'erreur et son explication s'affichent par appareil. Cas fréquents : redémarrage en attente, règle de détection d'une application Win32 qui ne trouve pas l'application installée, dépendance manquante.
  3. Après correction (paquet, règle de détection, dépendance), les appareils réessaient seuls ; pour un poste précis : Appareils > le poste > Synchroniser.
  4. Applications de sécurité attendues (agent de sécurité, VPN, Microsoft Authenticator) : vérifiez qu'elles sont attribuées en « Obligatoire » aux bons groupes.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le nombre d'installations en échec baisse pour les applications corrigées (relancez le script après quelques jours).
  • Relancez un audit : INT-006 passe conforme quand il ne reste plus d'échec.

Documentation Microsoft : learn.microsoft.com/en-us/mem/intune/apps/apps-add

INT-007

Politiques de protection des applications (MAM)

Sévérité élevée
Ce qui est vérifié
Des stratégies de protection des applications (MAM) doivent être configurées pour iOS et Android. Elles protègent les données de l'entreprise dans les applications mobiles, même sur un téléphone personnel non inscrit dans Intune.
Valeur attendue
Au moins une stratégie MAM active pour iOS et pour Android.

Temps estimé1 h, puis communication aux utilisateurs

RéférentielsCIS M365 v3.0 section 9ISO 27001 A.8.7NIS2 Art.21ANSSI Hygiène mesure 33RGPD Art.32.1.b

À savoir avant de commencer : Les utilisateurs devront saisir un code ou utiliser la biométrie pour ouvrir Outlook, Teams ou OneDrive sur leur téléphone, et le copier-coller vers leurs applications personnelles sera bloqué. Prévenez-les avant d'activer la stratégie.

Corriger dans le portail

  1. Centre d'administration Intune > Applications > Stratégies de protection des applications > Créer une stratégie > iOS/iPadOS.
  2. Applications : « Toutes les applications Microsoft » (ou au moins Outlook, Teams, OneDrive, Edge).
  3. Protection des données : envoyer les données de l'organisation vers les applications gérées par la stratégie seulement ; copier-coller limité aux applications gérées ; enregistrement des copies dans OneDrive et SharePoint seulement.
  4. Conditions d'accès : code PIN (ou biométrie) exigé. Lancement conditionnel : appareils jailbreakés ou rootés = Bloquer l'accès ; hors ligne depuis 90 jours = Effacer les données.
  5. Attribuez à « Tous les utilisateurs » (ou à un groupe pilote d'abord), puis faites la même stratégie pour Android.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script montre au moins une stratégie attribuée pour iOS et une pour Android.
  • Sur un téléphone de test, Outlook demande un code PIN et refuse le copier-coller vers une application personnelle.

Documentation Microsoft : learn.microsoft.com/en-us/mem/intune/apps/app-protection-policy

INT-008

Windows Hello for Business configuré

Sévérité moyenne
Ce qui est vérifié
Windows Hello for Business doit être déployé pour remplacer le mot de passe par une authentification biométrique ou un code PIN lié à l'appareil sur les postes Windows gérés.
Valeur attendue
Stratégie Windows Hello for Business active sur les appareils Windows.

Temps estimé30 min

RéférentielsCIS M365 v3.0 section 1ISO 27001 A.8.5NIS2 Art.21ANSSI Hygiène mesure 13RGPD Art.32.1.b

À savoir avant de commencer : Windows Hello Entreprise s'active à la prochaine connexion de l'utilisateur, qui doit alors créer un code PIN (avec la MFA). Prévenez les utilisateurs et testez d'abord sur quelques postes.

Corriger dans le portail

  1. Centre d'administration Intune > Appareils > Inscription > Windows > Windows Hello Entreprise : « Configurer Windows Hello Entreprise » = Activé (réglage pour tout le tenant, appliqué à l'inscription).
  2. Ou, pour cibler un groupe : Sécurité des points de terminaison > Protection de compte > Créer une stratégie > Windows > Protection de compte, Windows Hello Entreprise activé.
  3. Longueur minimale du PIN : 6 chiffres au moins ; autorisez la biométrie si les postes ont une caméra ou un lecteur d'empreinte compatibles.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script affiche state = enabled pour la configuration par défaut (ou une stratégie Protection de compte est attribuée).
  • Sur un poste de test, la connexion propose le code PIN Windows Hello après la prochaine ouverture de session.

Documentation Microsoft : learn.microsoft.com/en-us/windows/security/identity-protection/hello-for-business/ · learn.microsoft.com/en-us/mem/intune/protect/windows-hello

INT-009

Anneaux Windows Update configurés et attribués

Sévérité élevée
Ce qui est vérifié
Vérifie qu'au moins un anneau de mises à jour Windows est attribué aux appareils, sans pause, avec un report des correctifs de 14 jours au plus et une échéance d'installation de 7 jours au plus.
Valeur attendue
Anneau attribué, sans pause, report des correctifs de 14 jours au plus, échéance de 7 jours au plus.

Temps estimé20 min

RéférentielsCIS Intune WindowsISO 27001 A.8.8NIS2 Art.21ANSSI Hygiène mesure 34RGPD Art.32.1.b

À savoir avant de commencer : Une échéance courte redémarre les postes rapidement après l'installation des correctifs. Gardez 2 jours de grâce, et testez sur un anneau pilote (l'équipe informatique) avant tous les postes.

Corriger dans le portail

  1. Centre d'administration Intune > Appareils > Windows > Anneaux de mise à jour Windows 10 et ultérieur : ouvrez l'anneau cité (ou créez-en un).
  2. Paramètres : report des mises à jour de qualité de 0 à 7 jours ; échéance des mises à jour de qualité de 2 à 7 jours ; période de grâce de 2 jours ; aucune pause en cours.
  3. Attributions : « Tous les appareils » ou le groupe de tous les postes Windows ; un anneau pilote avec un report de 0 jour pour l'informatique est recommandé.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script affiche pour chaque anneau attribué : report de 14 jours au plus, échéance de 7 jours au plus, pas de pause.
  • Rapports > Mises à jour Windows : les postes installent les correctifs du mois dans la semaine.

Documentation Microsoft : learn.microsoft.com/en-us/mem/intune/protect/windows-10-update-rings

INT-010

Bases de sécurité Intune à jour

Sévérité moyenne
Ce qui est vérifié
Vérifie que les bases de sécurité Intune attribuées (Windows, Defender for Endpoint, Edge, Microsoft 365 Apps) utilisent la dernière version publiée par Microsoft.
Valeur attendue
Toutes les bases de sécurité attribuées sur la dernière version.

Temps estimé1 h par base, test pilote compris

RéférentielsCIS Intune WindowsISO 27001 A.8.9NIS2 Art.21ANSSI Hygiène mesure 14ANSSI Hygiène mesure 16RGPD Art.32.1.b

À savoir avant de commencer : Une nouvelle version de base peut ajouter des règles plus strictes (blocage de macros, de pilotes, de protocoles anciens). Comparez les paramètres et testez sur un groupe pilote avant de l'attribuer à tous les postes.

Corriger dans le portail

  1. Centre d'administration Intune > Sécurité des points de terminaison > Bases de sécurité : ouvrez le type de base cité (Windows, Microsoft Defender for Endpoint, Edge, Microsoft 365 Apps).
  2. Ouvrez le profil sur une version dépassée > « Mettre à jour » (ou « Changer de version ») vers la dernière version, en gardant vos personnalisations.
  3. Si la mise à jour directe n'est pas proposée : créez un profil sur la dernière version, reprenez vos exceptions, attribuez-le au groupe pilote, puis à tous, et supprimez l'ancien profil.
  4. Supprimez aussi les profils non attribués restés sur une ancienne version.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Chaque base attribuée est sur la dernière version proposée dans le portail.
  • Relancez un audit : INT-010 passe conforme.

Documentation Microsoft : learn.microsoft.com/en-us/mem/intune/protect/security-baselines-configure
