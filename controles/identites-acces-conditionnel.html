Audit des identités Entra ID et de l'accès conditionnel

Les comptes sont la première cible d'une attaque sur Microsoft 365 : un administrateur sans MFA, un protocole hérité encore ouvert ou un compte oublié suffisent souvent à prendre pied dans le tenant. Ces 9 contrôles vérifient l'hygiène des comptes Entra ID et les stratégies d'accès conditionnel qui les protègent.

IAM-001

Nombre d'administrateurs globaux

Sévérité élevée
Ce qui est vérifié
Compte les titulaires du rôle Administrateur général. Plus ils sont nombreux, plus la prise de contrôle totale du tenant est facile.
Valeur attendue
4 administrateurs généraux au plus.

Temps estimé30 min à 1 h

RéférentielsCIS M365 v3.0 section 1ISO 27001 A.5.15NIS2 Art.21ANSSI Hygiène mesure 5ANSSI Hygiène mesure 9RGPD Art.32.1.b

À savoir avant de commencer : Gardez au moins 2 administrateurs généraux, dont un compte d'accès d'urgence (voir IAM-006). Prévenez les personnes concernées avant de leur retirer le rôle.

Corriger dans le portail

  1. Centre d'administration Microsoft Entra > Identité > Rôles et administrateurs > Rôles et administrateurs.
  2. Ouvrez « Administrateur général » > Attributions : notez qui l'a et pour quel besoin réel.
  3. Pour chaque personne, attribuez le rôle qui suffit à son travail (Administrateur Exchange, SharePoint, des utilisateurs, du support technique…), puis retirez-lui « Administrateur général ».
  4. Avec Entra ID P2 : passez les administrateurs restants en « Éligible » dans Privileged Identity Management (activation à la demande, limitée dans le temps).
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Rôles et administrateurs > Administrateur général : 4 comptes ou moins (comptes d'urgence compris).
  • Les personnes qui ont perdu le rôle peuvent toujours faire leur travail avec leur nouveau rôle.

Documentation Microsoft : learn.microsoft.com/en-us/entra/identity/role-based-access-control/best-practices

IAM-002

Protection MFA des comptes administrateurs

Sévérité critique
Ce qui est vérifié
Vérifie que tous les comptes titulaires d'un rôle d'administration sont protégés par l'authentification multifacteur (MFA).
Valeur attendue
100 % des comptes administrateurs couverts.

Temps estimé15 min par compte

RéférentielsCIS M365 v3.0 section 1ISO 27001 A.8.5NIS2 Art.21ANSSI Hygiène mesure 13RGPD Art.32.1.b

À savoir avant de commencer : Un compte d'accès d'urgence doit lui aussi avoir une méthode forte : de préférence une clé de sécurité FIDO2 rangée au coffre.

Corriger dans le portail

  1. Centre d'administration Microsoft Entra > Protection > Méthodes d'authentification > Détails de l'inscription de l'utilisateur.
  2. Filtrez sur « Administrateur » = Oui et « Inscrit à l'authentification multifacteur » = Non : ce sont les comptes à traiter.
  3. Demandez à chaque titulaire d'inscrire Microsoft Authenticator ou une clé FIDO2 sur aka.ms/mysecurityinfo (de préférence une clé FIDO2 ou Windows Hello pour les administrateurs).
  4. Pour imposer la MFA à chaque connexion d'un administrateur, créez la stratégie d'accès conditionnel de CA-002.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script ne renvoie plus aucun compte.
  • Détails de l'inscription de l'utilisateur : tous les administrateurs sont « Inscrit à l'authentification multifacteur » = Oui.

Documentation Microsoft : learn.microsoft.com/en-us/entra/identity/authentication/concept-mfa-howitworks

IAM-003

Comptes invités sans activité récente

Sévérité moyenne
Ce qui est vérifié
Repère les comptes invités (B2B) qui ne se sont pas connectés depuis plus de 90 jours.
Valeur attendue
Aucun invité inactif depuis plus de 90 jours.

Temps estimé30 min, puis revue trimestrielle

RéférentielsCIS M365 v3.0 section 1ISO 27001 A.5.15NIS2 Art.21ANSSI Hygiène mesure 6RGPD Art.32.1.bRGPD Art.5.1.e

À savoir avant de commencer : Bloquez d'abord les invités (réversible) ; ne les supprimez qu'après un délai de 30 jours sans réclamation.

Corriger dans le portail

  1. Centre d'administration Microsoft Entra > Identité > Utilisateurs > Tous les utilisateurs.
  2. Filtre « Type d'utilisateur » = Invité, et ajoutez la colonne « Dernière date de connexion » ; triez par cette colonne.
  3. Pour chaque invité sans connexion depuis plus de 90 jours : ouvrez-le > Modifier les propriétés > Paramètres > décochez « Compte activé ».
  4. Avec Entra ID P2 : Gouvernance des identités > Révisions d'accès > Nouvelle révision d'accès, portée « Utilisateurs invités uniquement », tous les 3 mois, refus automatique sans réponse.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script ne renvoie plus aucun invité actif sans connexion depuis 90 jours.
  • Une révision d'accès récurrente est planifiée pour les invités (si Entra ID P2).

Documentation Microsoft : learn.microsoft.com/en-us/entra/id-governance/access-reviews-overview

IAM-004

Comptes administrateurs avec une boîte mail

Sévérité élevée
Ce qui est vérifié
Les comptes d'administration privilégiés ne devraient pas avoir de boîte aux lettres : un e-mail d'hameçonnage ouvert avec un compte administrateur donne directement les droits les plus élevés.
Valeur attendue
Aucun compte administrateur avec une boîte aux lettres.

Temps estimé1 h par administrateur

RéférentielsCIS M365 v3.0 section 1ISO 27001 A.5.15NIS2 Art.21ANSSI Hygiène mesure 8ANSSI Hygiène mesure 27RGPD Art.32.1.b

À savoir avant de commencer : Ne retirez pas la licence Exchange du compte de tous les jours d'une personne : sa boîte serait supprimée après 30 jours. Le bon geste est de lui créer un compte d'administration séparé.

Corriger dans le portail

  1. Centre d'administration Microsoft 365 > Utilisateurs > Utilisateurs actifs > Ajouter un utilisateur : créez un compte dédié (ex. adm-prenom.nom@<domaine>.onmicrosoft.com), sans licence.
  2. Centre d'administration Microsoft Entra > Rôles et administrateurs : attribuez à ce nouveau compte les rôles de la personne (de préférence en « Éligible » avec PIM).
  3. Testez la connexion du nouveau compte, puis retirez les rôles d'administration du compte de tous les jours (qui garde sa boîte mail).
  4. Le compte d'administration ne sert qu'aux portails d'administration, jamais à lire ses mails ou naviguer.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Rôles et administrateurs : les rôles sont portés par les comptes adm-…, plus par les comptes de tous les jours.
  • Utilisateurs actifs : les comptes adm-… n'ont aucune licence (donc aucune boîte mail).
IAM-005

Comptes actifs sans connexion depuis plus de 90 jours

Sévérité moyenne
Ce qui est vérifié
Les comptes actifs (non bloqués) sans connexion depuis 90 jours augmentent inutilement la surface d'attaque : personne ne remarquera qu'un attaquant les utilise.
Valeur attendue
Aucun compte actif sans connexion depuis plus de 90 jours.

Temps estimé30 min, puis chaque mois

RéférentielsCIS M365 v3.0 section 1ISO 27001 A.5.15NIS2 Art.21ANSSI Hygiène mesure 6RGPD Art.32.1.b

À savoir avant de commencer : Vérifiez avec les RH ou les responsables avant de bloquer : comptes de service, salles, absences longues. Bloquer est réversible ; la suppression ne l'est que pendant 30 jours.

Corriger dans le portail

  1. Centre d'administration Microsoft Entra > Identité > Utilisateurs > Tous les utilisateurs.
  2. Filtres « Type d'utilisateur » = Membre et « Compte activé » = Oui ; ajoutez la colonne « Dernière date de connexion » et triez.
  3. Pour chaque compte sans connexion depuis plus de 90 jours et sans besoin confirmé : Modifier les propriétés > Paramètres > décochez « Compte activé », puis retirez ses licences (voir aussi LIC-005).
  4. Mettez en place une procédure de départ : blocage du compte le dernier jour, suppression après 30 jours.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script ne renvoie plus que les comptes de la liste à garder.
  • Les licences des comptes bloqués sont libérées (Licences > réattribution possible).
IAM-006

Comptes d'accès d'urgence (break-glass) configurés

Sévérité élevée
Ce qui est vérifié
Au moins un compte d'accès d'urgence (break-glass) doit être exclu de toutes les stratégies d'accès conditionnel, pour garder l'accès au tenant si une stratégie bloque tout le monde par erreur.
Valeur attendue
1 ou 2 comptes d'urgence exclus de toutes les stratégies d'accès conditionnel.

Temps estimé1 h

RéférentielsCIS M365 v3.0 section 1ISO 27001 A.5.15NIS2 Art.21ANSSI Hygiène mesure 5RGPD Art.32.1.c

À savoir avant de commencer : Le compte d'urgence doit être un administrateur général permanent (pas seulement éligible), exclu de TOUTES les stratégies d'accès conditionnel actives — c'est ce que vérifie le contrôle.

Corriger dans le portail

  1. Entra > Utilisateurs > Nouvel utilisateur : créez 1 ou 2 comptes sur le domaine …onmicrosoft.com (ex. urgence01@<tenant>.onmicrosoft.com), sans licence, avec un mot de passe long (25 caractères ou plus) rangé au coffre, hors ligne.
  2. Rôles et administrateurs > Administrateur général > Ajouter des attributions : attribution « Active » et « Permanente ».
  3. Groupes > Nouveau groupe de sécurité « CA - Exclusion comptes d'urgence » avec ces comptes ; dans chaque stratégie d'accès conditionnel active : Utilisateurs > Exclure > ce groupe.
  4. Enregistrez de préférence une clé FIDO2 sur chaque compte, et créez une alerte sur toute connexion de ces comptes (Microsoft Sentinel ou règle d'alerte Log Analytics sur les journaux de connexion).
  5. Testez la connexion une fois par trimestre et notez-le.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Chaque stratégie d'accès conditionnel active : Utilisateurs > Exclure contient le groupe des comptes d'urgence.
  • Une connexion de test avec le compte d'urgence réussit et déclenche l'alerte.
CA-001

Blocage de l'authentification héritée (legacy auth)

Sévérité critique
Ce qui est vérifié
Vérifie qu'une stratégie d'accès conditionnel bloque l'authentification héritée (SMTP, IMAP, POP3, ActiveSync de base), qui ne sait pas faire de MFA et sert aux attaques par pulvérisation de mots de passe.
Valeur attendue
Authentification héritée bloquée par au moins une stratégie active.

Temps estimé30 min + 7 jours d'observation

RéférentielsCIS M365 v3.0 section 2ISO 27001 A.8.2NIS2 Art.21ANSSI Hygiène mesure 13ANSSI Hygiène mesure 21RGPD Art.32.1.b

À savoir avant de commencer : Avant d'activer, regardez dans les journaux de connexion (filtre « Application cliente » = autres clients / Exchange ActiveSync) qui utilise encore l'authentification héritée : imprimantes ou scanners en SMTP, vieux clients mail.

Corriger dans le portail

  1. Centre d'administration Microsoft Entra > Protection > Accès conditionnel > Stratégies > Nouvelle stratégie (ou modèle « Bloquer l'authentification héritée »).
  2. Utilisateurs : Inclure « Tous les utilisateurs » ; Exclure le groupe des comptes d'urgence (IAM-006).
  3. Ressources cibles : « Toutes les ressources » (toutes les applications cloud).
  4. Conditions > Applications clientes : cochez seulement « Clients Exchange ActiveSync » et « Autres clients ».
  5. Accorder : « Bloquer l'accès ». Activer la stratégie : « Rapport seul » pendant 7 jours, puis « Activé ».
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Accès conditionnel > Stratégies : la stratégie est « Activé », vise tous les utilisateurs et toutes les ressources, avec au plus 2 comptes exclus.
  • Journaux de connexion, filtre « Application cliente » = autres clients : les tentatives sont en échec « Accès conditionnel ».

Documentation Microsoft : learn.microsoft.com/en-us/entra/identity/conditional-access/block-legacy-authentication

CA-002

MFA obligatoire pour tous les administrateurs

Sévérité critique
Ce qui est vérifié
Vérifie qu'une stratégie d'accès conditionnel impose la MFA à tous les comptes qui ont un rôle d'administration.
Valeur attendue
Au moins une stratégie impose la MFA aux administrateurs.

Temps estimé30 min + 3 jours d'observation

RéférentielsCIS M365 v3.0 section 2ISO 27001 A.8.5NIS2 Art.21ANSSI Hygiène mesure 13RGPD Art.32.1.b

À savoir avant de commencer : Vérifiez d'abord que chaque administrateur a inscrit une méthode MFA (IAM-002), sinon il sera bloqué à sa prochaine connexion.

Corriger dans le portail

  1. Accès conditionnel > Stratégies > Nouvelle stratégie (ou modèle « Exiger l'authentification multifacteur pour les administrateurs »).
  2. Utilisateurs : Inclure > Rôles d'annuaire : au minimum Administrateur général, de rôle privilégié, de la sécurité, Exchange, SharePoint, des utilisateurs, du support technique, de l'accès conditionnel, d'applications, d'applications cloud, d'authentification, d'authentification privilégié, de facturation, des mots de passe.
  3. Exclure : le groupe des comptes d'urgence uniquement.
  4. Ressources cibles : « Toutes les ressources ». Accorder : « Exiger l'authentification multifacteur » (ou mieux, « Exiger la force d'authentification » > MFA résistante au hameçonnage).
  5. Activer : « Rapport seul » quelques jours, puis « Activé ».
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • La stratégie est « Activé » et seuls les comptes d'urgence en sont exclus.
  • Journaux de connexion d'un administrateur : « Exigence d'authentification » = authentification multifacteur.

Documentation Microsoft : learn.microsoft.com/en-us/entra/identity/conditional-access/howto-conditional-access-policy-admin-mfa

CA-003

Exclusions trop larges dans les politiques d'accès conditionnel

Sévérité élevée
Ce qui est vérifié
Repère les stratégies d'accès conditionnel qui excluent des groupes ou des utilisateurs sans justification : chaque exclusion est une porte ouverte.
Valeur attendue
Aucune exclusion non documentée.

Temps estimé1 h, puis revue trimestrielle

RéférentielsCIS M365 v3.0 section 2ISO 27001 A.5.15NIS2 Art.21ANSSI Hygiène mesure 9ANSSI Hygiène mesure 13RGPD Art.32.1.b

À savoir avant de commencer : Ne retirez pas une exclusion sans savoir pourquoi elle a été posée : demandez au propriétaire de la stratégie, et testez avec l'outil « What If ».

Corriger dans le portail

  1. Accès conditionnel > Stratégies : ouvrez chaque stratégie citée ci-dessus > Utilisateurs > Exclure.
  2. Pour chaque compte ou groupe exclu, notez la raison. Les comptes d'urgence (IAM-006) sont la seule exclusion permanente normale.
  3. Retirez les exclusions sans justification. Pour un besoin temporaire, utilisez un groupe dédié (ex. « CA - Exclusion temporaire ») avec une date de fin, revu chaque trimestre.
  4. Vérifiez l'effet avec Accès conditionnel > What If, sur un compte qui était exclu.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Aucune stratégie active n'exclut plus de 2 comptes, groupes compris (en dehors des comptes d'urgence).
  • Chaque exclusion restante a une raison écrite et une date de revue.
