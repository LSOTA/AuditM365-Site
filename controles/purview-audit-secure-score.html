Audit de Microsoft Purview, du journal d'audit et du Secure Score

Sans journal d'audit, impossible de reconstituer un incident ; sans étiquettes de confidentialité, impossible de protéger un document là où il circule. Ces 7 contrôles vérifient le journal d'audit unifié et sa durée de conservation, les étiquettes de confidentialité, les stratégies d'alerte, le Microsoft Secure Score et les changements annoncés par Microsoft qui demandent une action de l'administrateur.

PUR-001

Journal d'audit unifié actif

Sévérité élevée
Ce qui est vérifié
Vérifie que le journal d'audit unifié de Microsoft 365 est activé pour tracer les activités des utilisateurs et des administrateurs.
Valeur attendue
Journal d'audit unifié activé.

Temps estimé5 min, puis jusqu'à 60 min avant les premiers événements

RéférentielsCIS M365 v3.0 section 10ISO 27001 A.8.15NIS2 Art.21ANSSI Hygiène mesure 36RGPD Art.32.1.dRGPD Art.33

À savoir avant de commencer : L'activation ne se fait qu'une fois et ne coûte rien. Les activités antérieures à l'activation ne sont pas récupérables : activez dès maintenant, sans attendre un incident.

Corriger dans le portail

  1. Portail Microsoft Purview > Solutions > Audit.
  2. Si un bandeau « Commencer l'enregistrement des activités des utilisateurs et des administrateurs » s'affiche, cliquez dessus : l'audit était désactivé.
  3. Sans bandeau, l'audit est déjà actif : lancez une recherche sur les dernières 24 h pour vérifier que des événements remontent.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script affiche « Journal d'audit unifié actif : True ».
  • Purview > Audit : une recherche sur les dernières 24 h renvoie des événements.

Documentation Microsoft : learn.microsoft.com/en-us/microsoft-365/compliance/turn-audit-log-search-on-or-off

PUR-002

Étiquettes de confidentialité configurées et publiées

Sévérité moyenne
Ce qui est vérifié
Au moins une étiquette de confidentialité doit être publiée dans une stratégie pour permettre la classification des documents et des e-mails.
Valeur attendue
Au moins une étiquette publiée.

Temps estimé1 h pour créer et publier, plus la communication aux utilisateurs

RéférentielsCIS M365 v3.0 section 10ISO 27001 A.8.12NIS2 Art.21ANSSI Hygiène mesure 4RGPD Art.32.1.a

À savoir avant de commencer : Publier une étiquette la fait apparaître dans Outlook, Word, Excel et Teams de tous les utilisateurs visés. Commencez par un groupe pilote, sans chiffrement ni étiquette obligatoire : une étiquette qui chiffre mal réglée peut rendre des documents illisibles pour des destinataires externes.

Corriger dans le portail

  1. Portail Microsoft Purview > Solutions > Protection des informations > Étiquettes de confidentialité > Créer une étiquette.
  2. Créez une gamme simple, par exemple « Public », « Interne », « Confidentiel » : nom, info-bulle pour l'utilisateur, étendue « Fichiers et e-mails », sans chiffrement pour commencer.
  3. Onglet « Stratégies de publication » > Publier des étiquettes : choisissez les étiquettes, puis le groupe pilote ; laissez « étiquette par défaut » et « justification obligatoire » désactivées au début.
  4. Après 2 à 4 semaines sans problème, élargissez la stratégie à tous les utilisateurs.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script affiche au moins une étiquette et une stratégie de publication.
  • Dans Outlook ou Word, un utilisateur du groupe voit le bouton « Confidentialité » avec les étiquettes (jusqu'à 24 h après la publication).
  • Relancez un audit : PUR-002 passe à Conforme.

Documentation Microsoft : learn.microsoft.com/en-us/microsoft-365/compliance/create-sensitivity-labels

PUR-003

Microsoft Secure Score

Sévérité moyenne
Ce qui est vérifié
Le Microsoft Secure Score doit atteindre au moins la moitié du score maximum pour indiquer un niveau de maturité acceptable.
Valeur attendue
50 % du score maximum au moins.

Temps estiméVariable : quelques heures réparties sur plusieurs semaines

RéférentielsCIS M365 v3.0 section 10ISO 27001 A.8.16NIS2 Art.21ANSSI Hygiène mesure 38RGPD Art.32.1.d

À savoir avant de commencer : Le Secure Score est un indicateur, pas une fin : traitez d'abord les actions à fort impact et faible effet sur les utilisateurs. Une action marquée « Risque accepté » ou « Résolu par un tiers » doit l'être pour une vraie raison, documentée.

Corriger dans le portail

  1. Portail Microsoft Defender > Exposition > Secure Score (ou security.microsoft.com/securescore) > onglet Actions recommandées.
  2. Triez par « Impact sur le score » et filtrez sur « À traiter » : commencez par les actions dont l'impact utilisateur est faible.
  3. Ouvrez chaque action : la fiche donne la marche à suivre et le lien du portail concerné. Les contrôles d'AuditM365 renvoient à plusieurs de ces actions (MFA, accès conditionnel, Safe Links...).
  4. Une action déjà couverte par un autre outil : statut « Résolu par un tiers », avec une note.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script affiche un score d'au moins 50 %.
  • Relancez un audit : PUR-003 passe à Conforme (le Secure Score se met à jour une fois par jour).

Documentation Microsoft : learn.microsoft.com/en-us/microsoft-365/security/defender/microsoft-secure-score

PUR-004

Conservation des journaux d'audit d'au moins 90 jours

Sévérité moyenne
Ce qui est vérifié
Les journaux d'audit doivent être conservés au moins 90 jours pour permettre les investigations après un incident.
Valeur attendue
Conservation de 90 jours au moins.

Temps estimé15 min

RéférentielsCIS M365 v3.0 section 10ISO 27001 A.8.15NIS2 Art.21ANSSI Hygiène mesure 36RGPD Art.33RGPD Art.32.1.d

À savoir avant de commencer : Les stratégies de conservation personnalisées demandent Audit (Premium) (E5, A5, G5 ou module complémentaire). Sans elle, la conservation par défaut s'applique (180 jours en Audit Standard) : rien à configurer. Le point à surveiller est une stratégie personnalisée PLUS COURTE que 90 jours, qui écourte la conservation des activités qu'elle vise.

Corriger dans le portail

  1. Portail Microsoft Purview > Solutions > Audit > Stratégies > Stratégies de conservation de l'audit.
  2. Relisez chaque stratégie : durée, types d'enregistrements et utilisateurs visés. Toute stratégie de moins de 90 jours est à allonger ou à supprimer.
  3. Avec Audit (Premium) : créez au besoin une stratégie « 1 an » (ou plus) pour les activités sensibles (connexions Entra, Exchange, SharePoint), priorité élevée.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script n'affiche aucune stratégie « MOINS DE 90 JOURS ».
  • PUR-004 reste « non évaluable » si l'application d'audit n'a pas le rôle de lecture des stratégies : c'est voulu (rôle d'écriture chez Microsoft), la vérification se fait ici.

Documentation Microsoft : learn.microsoft.com/en-us/microsoft-365/compliance/audit-log-retention-policies

PUR-005

Alertes de sécurité actives

Sévérité moyenne
Ce qui est vérifié
Au moins une stratégie d'alerte doit être configurée et active pour prévenir les administrateurs en cas d'activité suspecte.
Valeur attendue
Au moins une stratégie d'alerte active.

Temps estimé20 min

RéférentielsCIS M365 v3.0 section 10ISO 27001 A.8.16NIS2 Art.21ANSSI Hygiène mesure 36ANSSI Hygiène mesure 40RGPD Art.33

À savoir avant de commencer : Les stratégies d'alerte par défaut de Microsoft couvrent l'essentiel (transfert suspect, élévation de privilège, programme malveillant...). Le risque le plus courant est qu'elles soient désactivées, ou que personne ne reçoive les notifications : vérifiez les destinataires.

Corriger dans le portail

  1. Portail Microsoft Defender > E-mail et collaboration > Stratégies et règles > Stratégie d'alerte (ou Portail Purview > Stratégies > Stratégies d'alerte).
  2. Filtrez sur « Gravité : Élevée » : chaque stratégie doit être « Activée ».
  3. Ouvrez les stratégies importantes > Modifier > Destinataires : ajoutez une boîte suivie (équipe informatique ou prestataire), pas seulement les administrateurs généraux.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script n'affiche plus aucune stratégie de gravité élevée « Desactivee : True ».
  • Les stratégies importantes ont au moins un destinataire suivi.

Documentation Microsoft : learn.microsoft.com/en-us/microsoft-365/compliance/alert-policies

PUR-006

Étiquettes de confidentialité appliquées aux groupes et équipes

Sévérité moyenne
Ce qui est vérifié
Vérifie que les étiquettes de confidentialité sont activées pour les groupes et les sites (paramètre EnableMIPLabels) et appliquées à au moins 80 % des groupes Microsoft 365 et équipes Teams.
Valeur attendue
Étiquettes activées pour les groupes ; au moins 80 % des groupes et équipes étiquetés.

Temps estimé1 h, plus l'étiquetage des groupes existants

RéférentielsISO 27001 A.5.12ISO 27001 A.5.13NIS2 Art.21ANSSI Hygiène mesure 4ANSSI Hygiène mesure 9RGPD Art.25

À savoir avant de commencer : Prérequis : des étiquettes de confidentialité publiées (PUR-002). L'activation pour les groupes ne change rien aux groupes existants : ils restent sans étiquette tant qu'on ne leur en attribue pas une. Rendre l'étiquette obligatoire à la création des équipes ne s'applique qu'aux nouvelles équipes.

Corriger dans le portail

  1. Activez d'abord les étiquettes pour les groupes avec le script (paramètre EnableMIPLabels), puis lancez la synchronisation (Execute-AzureAdLabelSync, dernière ligne du script).
  2. Portail Microsoft Purview > Protection des informations > Étiquettes de confidentialité : modifiez chaque étiquette concernée > Étendue : cochez « Groupes et sites », puis réglez la confidentialité (privé / public) et l'accès des invités.
  3. Centre d'administration Teams ou SharePoint : ouvrez chaque équipe ou site sans étiquette et attribuez-lui l'étiquette adaptée (ou demandez-le aux propriétaires).
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script affiche « EnableMIPLabels : True » et moins de 20 % de groupes sans étiquette.
  • Relancez un audit : PUR-006 passe à Conforme.

Documentation Microsoft : learn.microsoft.com/en-us/purview/sensitivity-labels-teams-groups-sites

PUR-007

Changements Microsoft à action requise

Sévérité faible
Ce qui est vérifié
Liste les annonces du centre de messages Microsoft 365 qui concernent l'administrateur avec une échéance d'action dans les 60 prochains jours ; celles des 30 prochains jours qui sont un changement majeur, un retrait ou une « Action required » sont à traiter en priorité.
Valeur attendue
Aucune action requise par Microsoft en attente, ou chacune suivie.

Temps estimé15 à 30 min par semaine

RéférentielsISO 27001 A.8.32NIS2 Art.21ANSSI Hygiène mesure 34ANSSI Hygiène mesure 35RGPD Art.32.1.d

À savoir avant de commencer : Toutes les annonces ne concernent pas le tenant : vérifiez le service et les fonctions visés avant d'agir. Un retrait non anticipé (ancien protocole, ancienne API) peut couper un logiciel métier ou un appareil (imprimante, scanner) à la date annoncée.

Corriger dans le portail

  1. Centre d'administration Microsoft 365 > Santé > Centre de messages : filtrez sur « Action requise » et triez par date d'action.
  2. Pour chaque annonce : vérifiez si le tenant utilise le service ou la fonction, planifiez l'action avant l'échéance, puis archivez l'annonce.
  3. Paramètres du centre de messages (« Préférences ») : activez le résumé hebdomadaire par e-mail vers une boîte suivie.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script n'affiche plus d'annonce non traitée dont l'échéance est dans les 30 jours.
  • Relancez un audit : PUR-007 passe à Conforme.

Documentation Microsoft : learn.microsoft.com/en-us/microsoft-365/admin/manage/message-center
