Audit de Defender for Endpoint

Microsoft Defender for Endpoint détecte et bloque les attaques sur les postes et les serveurs, à condition que les appareils y soient intégrés et que ses alertes soient traitées. Ces 5 contrôles mesurent le taux d'intégration, les alertes élevées en attente, le score d'exposition, le score de sécurité des appareils et le déploiement d'une base de sécurité Windows.

MDE-001

Taux d'intégration des appareils dans Defender for Endpoint

Sévérité élevée
Ce qui est vérifié
Au moins 90 % des appareils gérés doivent être intégrés à Microsoft Defender for Endpoint pour bénéficier de la détection et de la réponse (EDR).
Valeur attendue
90 % des appareils gérés intégrés au moins.

Temps estimé1 à 2 h, puis le temps du déploiement sur le parc

RéférentielsCIS M365 v3.0 section 9ISO 27001 A.8.7NIS2 Art.21ANSSI Hygiène mesure 14ANSSI Hygiène mesure 16RGPD Art.32.1.b

À savoir avant de commencer : L'intégration demande une licence Defender for Endpoint (Plan 1, Plan 2, Business, ou incluse dans Microsoft 365 E5 / Business Premium). Déployez d'abord sur un groupe pilote : sur un poste avec un autre antivirus, Defender passe en mode passif, vérifiez la compatibilité avec l'éditeur.

Corriger dans le portail

  1. Portail Microsoft Defender > Paramètres > Points de terminaison > Fonctionnalités avancées : activez « Connexion à Microsoft Intune ».
  2. Centre d'administration Microsoft Intune > Administration du locataire > Connecteurs et jetons > Microsoft Defender for Endpoint : activez la connexion des appareils Windows (et macOS, iOS, Android si utilisés).
  3. Intune > Sécurité du point de terminaison > Détection et réponse de point de terminaison > Créer une stratégie : Windows, profil « Détection et réponse de point de terminaison », type de package « Automatique à partir du connecteur », affectée au groupe pilote puis à tous les appareils.
  4. Portail Defender > Appareils (Inventaire) : les appareils apparaissent sous quelques heures avec l'état « Intégré ».
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script affiche au moins 90 % des appareils Windows intégrés.
  • Relancez un audit : MDE-001 passe à Conforme.

MDE-002

Alertes Defender for Endpoint élevées ou critiques

Sévérité élevée
Ce qui est vérifié
Aucune alerte active de gravité élevée ou critique ne doit rester sans traitement dans Microsoft Defender for Endpoint.
Valeur attendue
Aucune alerte élevée ou critique en attente.

Temps estimé15 à 60 min par alerte

RéférentielsCIS M365 v3.0 section 9ISO 27001 A.8.16NIS2 Art.21ANSSI Hygiène mesure 40RGPD Art.33

À savoir avant de commencer : Une alerte élevée ou critique se traite comme un incident possible : ne la fermez pas sans avoir regardé l'arbre du processus, l'appareil et l'utilisateur. En cas de doute (rançongiciel, vol d'identifiants), isolez l'appareil depuis sa page avant d'enquêter. Fermer une alerte sans enquête efface le signal, pas la menace.

Corriger dans le portail

  1. Portail Microsoft Defender > Incidents et alertes > Alertes : filtrez sur « Source : EDR / Defender pour point de terminaison », « Gravité : Élevée, Haute » et « État : Nouveau, En cours ».
  2. Ouvrez chaque alerte : chronologie, arbre du processus, fichiers et appareils touchés. Attribuez-la à une personne.
  3. Menace réelle : actions de réponse (isoler l'appareil, arrêter et mettre en quarantaine le fichier, analyse antivirus), puis changez le mot de passe de l'utilisateur.
  4. Fausse alerte confirmée : classez-la « Faux positif » avec une note ; si elle revient, créez une règle de suppression ciblée (jamais globale).
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script n'affiche plus aucune alerte (toutes résolues, après enquête).
  • Relancez un audit : MDE-002 passe à Conforme.

Documentation Microsoft : learn.microsoft.com/en-us/microsoft-365/security/defender-endpoint/manage-alerts · learn.microsoft.com/en-us/microsoft-365/security/defender-endpoint/investigate-alerts

MDE-003

Score d'exposition Defender for Endpoint

Sévérité moyenne
Ce qui est vérifié
Le score d'exposition de Defender for Endpoint mesure la vulnérabilité de l'organisation aux menaces : plus il est élevé, plus la surface d'attaque est grande.
Valeur attendue
Score d'exposition de 30 au plus.

Temps estiméVariable : chantier continu de mises à jour

RéférentielsCIS M365 v3.0 section 9ISO 27001 A.8.7NIS2 Art.21ANSSI Hygiène mesure 34ANSSI Hygiène mesure 38RGPD Art.32.1.d

À savoir avant de commencer : Le score d'exposition baisse surtout en mettant à jour les logiciels vulnérables (navigateurs, Java, Adobe, Office) et en retirant ceux qui ne servent plus. Testez les mises à jour de logiciels métier sur quelques postes avant de les déployer partout.

Corriger dans le portail

  1. Portail Microsoft Defender > Gestion des vulnérabilités > Recommandations : triez par « Impact sur l'exposition ».
  2. Ouvrez les premières recommandations : logiciel, versions vulnérables, appareils exposés. Déployez la mise à jour avec Intune (Applications ou Windows Update pour les entreprises) ou retirez le logiciel.
  3. Pour une recommandation qu'on ne peut pas suivre tout de suite : « Demander une correction » (tâche suivie) ou « Exception » datée, avec une justification.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Portail Defender > Gestion des vulnérabilités > Tableau de bord : le score d'exposition est à 30 ou moins.
  • Relancez un audit : MDE-003 passe à Conforme.

Documentation Microsoft : learn.microsoft.com/en-us/microsoft-365/security/defender-endpoint/tvm-exposure-score · learn.microsoft.com/en-us/microsoft-365/security/defender-endpoint/threat-and-vuln-mgt-overview

MDE-004

Score de sécurité des appareils

Sévérité moyenne
Ce qui est vérifié
Le score de sécurité des appareils mesure l'état des appareils gérés par rapport aux réglages de sécurité recommandés par Microsoft.
Valeur attendue
Score de sécurité des appareils de 70 % au moins.

Temps estimé2 à 4 h

RéférentielsCIS M365 v3.0 section 9ISO 27001 A.8.9NIS2 Art.21ANSSI Hygiène mesure 14ANSSI Hygiène mesure 38RGPD Art.32.1.d

À savoir avant de commencer : Les actions « Appareils » du Secure Score se règlent pour la plupart par des stratégies Intune (antivirus, pare-feu, BitLocker, réduction de la surface d'attaque). Appliquez-les d'abord à un groupe pilote : les règles de réduction de la surface d'attaque se mettent en mode Audit avant le mode Bloquer.

Corriger dans le portail

  1. Portail Microsoft Defender > Exposition > Secure Score > Actions recommandées : filtrez sur « Catégorie : Appareil » et « État : À traiter ».
  2. Pour chaque action : la fiche cite le réglage (par exemple « Activer la protection fournie par le cloud ») ; créez-le dans Intune > Sécurité du point de terminaison (Antivirus, Pare-feu, Chiffrement de disque, Réduction de la surface d'attaque).
  3. Une base de sécurité Windows (MDE-005) règle d'un coup une grande partie de ces actions.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script affiche un score des appareils d'au moins 70 %, sur plusieurs contrôles notés.
  • MDE-004 reste « non évaluable » tant que moins de quelques contrôles appareils sont notés (appareils non intégrés : voir MDE-001).

Documentation Microsoft : learn.microsoft.com/en-us/microsoft-365/security/defender-endpoint/tvm-microsoft-secure-score-devices · learn.microsoft.com/en-us/microsoft-365/security/defender-endpoint/configure-machines-security-baseline

MDE-005

Base de sécurité Windows déployée

Sévérité moyenne
Ce qui est vérifié
Une base de sécurité Windows doit être configurée et déployée sur les postes Windows, par Intune ou Defender for Endpoint, pour garantir une configuration minimale sécurisée.
Valeur attendue
Base de sécurité configurée pour les appareils Windows.

Temps estimé2 h pour le pilote, puis 2 à 4 semaines avant la généralisation

RéférentielsCIS M365 v3.0 section 9ISO 27001 A.8.9NIS2 Art.21ANSSI Hygiène mesure 14RGPD Art.32.1.b

À savoir avant de commencer : Une base de sécurité applique des centaines de réglages d'un coup (NTLM, SMB, macros, comptes locaux...) : elle peut bloquer une application métier ancienne, une imprimante ou un partage réseau. Affectez-la d'abord à un groupe pilote de quelques postes, vérifiez les applications métier, et ne modifiez que les réglages qui posent un problème réel, en le documentant.

Corriger dans le portail

  1. Centre d'administration Microsoft Intune > Sécurité du point de terminaison > Bases de référence de sécurité > « Base de référence de sécurité pour Windows 10 et versions ultérieures » > Créer un profil.
  2. Gardez les valeurs recommandées ; affectez le profil à un groupe pilote d'appareils.
  3. Après 2 à 4 semaines sans incident (ou après avoir ajusté les réglages bloquants), affectez-le à tous les appareils Windows.
  4. Ajoutez aussi la base « Microsoft Defender for Endpoint » si la licence le permet.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script affiche un profil « Base de référence de sécurité pour Windows » affecté (pilote, puis tous les appareils).
  • Intune > le profil > État de l'appareil : les appareils sont « Conforme » aux réglages ; relancez un audit, MDE-005 passe à Conforme.
