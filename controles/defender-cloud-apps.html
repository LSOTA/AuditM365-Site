Audit de Defender for Cloud Apps

Les utilisateurs se connectent chaque jour à des applications cloud que le service informatique n'a jamais validées, et accordent des droits à des applications OAuth tierces. Ces 4 contrôles s'appuient sur Microsoft Defender for Cloud Apps pour vérifier les alertes en attente, les applications OAuth à risque, les stratégies actives et le Shadow IT.

MCAS-001

Alertes Defender for Cloud Apps à traiter

Sévérité élevée
Ce qui est vérifié
Aucune alerte active de gravité critique ou élevée provenant de Microsoft Defender for Cloud Apps ne doit rester sans traitement.
Valeur attendue
Aucune alerte critique ou élevée en attente.

Temps estimé15 à 60 min par alerte

RéférentielsANSSI Hygiène mesure 40RGPD Art.33

À savoir avant de commencer : Une alerte Defender for Cloud Apps élevée (téléchargement massif, voyage impossible, règle de transfert suspecte) peut signaler un compte piraté : vérifiez avec l'utilisateur avant de la fermer, et suspendez le compte en cas de doute.

Corriger dans le portail

  1. Portail Microsoft Defender > Incidents et alertes > Alertes : filtre « Source : Defender for Cloud Apps », « Gravité : Élevée », « État : Nouveau, En cours ».
  2. Ouvrez chaque alerte : utilisateur, application, activité ; attribuez-la à une personne.
  3. Compromission : réinitialisez le mot de passe, révoquez les sessions, vérifiez les règles de boîte (EXO-005) ; fausse alerte : classez-la avec une note et ajustez la stratégie qui l'a produite.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script affiche « 0 » alerte élevée non résolue.
  • Relancez un audit : MCAS-001 passe à Conforme.

Documentation Microsoft : learn.microsoft.com/en-us/defender-cloud-apps/managing-alerts · learn.microsoft.com/en-us/microsoft-365/security/defender/investigate-alerts

MCAS-002

Applications OAuth non autorisées

Sévérité élevée
Ce qui est vérifié
Aucune application OAuth avec un score de risque élevé ne doit être présente dans la gouvernance des applications sans l'approbation explicite d'un administrateur.
Valeur attendue
Aucune application OAuth à risque élevé non approuvée.

Temps estimé30 min à 1 h

RéférentielsANSSI Hygiène mesure 3ANSSI Hygiène mesure 9RGPD Art.32.1.bRGPD Art.28

À savoir avant de commencer : Retirer le consentement d'une application coupe son accès pour tous les utilisateurs : vérifiez qu'elle n'est pas utilisée par un service (outil métier, synchronisation de calendrier). Pour la suite, limitez le consentement des utilisateurs aux éditeurs vérifiés (Entra > Applications d'entreprise > Consentement et autorisations).

Corriger dans le portail

  1. Centre d'administration Microsoft Entra > Applications > Applications d'entreprise : filtre « Type d'application : toutes », ouvrez les applications tierces citées par l'audit > Autorisations.
  2. Application inconnue ou inutile : Propriétés > « Activée pour que les utilisateurs se connectent » = Non (ou Supprimer), puis Autorisations > révoquer.
  3. Consentement et autorisations > Paramètres de consentement des utilisateurs : « Autoriser le consentement pour les applications d'éditeurs vérifiés, pour les autorisations sélectionnées ».
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Le script n'affiche plus d'application d'éditeur non vérifié avec des autorisations sensibles.
  • Relancez un audit : MCAS-002 passe à Conforme.

Documentation Microsoft : learn.microsoft.com/en-us/defender-cloud-apps/app-governance-manage-app-governance · learn.microsoft.com/en-us/defender-cloud-apps/app-permission-policy

MCAS-003

Politiques Defender for Cloud Apps actives

Sévérité moyenne
Ce qui est vérifié
Au moins une stratégie Defender for Cloud Apps doit être active pour surveiller et protéger l'usage des applications cloud.
Valeur attendue
Au moins une stratégie active.

Temps estimé1 h

RéférentielsANSSI Hygiène mesure 36RGPD Art.32.1.b

À savoir avant de commencer : Licence Microsoft Defender for Cloud Apps requise (incluse dans Microsoft 365 E5 / E5 Security). Les stratégies ne sont pas exposées par l'API Microsoft : AuditM365 ne peut pas les lire, d'où le statut « non évaluable » ; la vérification se fait dans le portail.

Corriger dans le portail

  1. Portail Microsoft Defender > Cloud Apps > Stratégies > Gestion des stratégies : vérifiez que des stratégies sont actives (onglets Détection des menaces, Protection des informations, Accès conditionnel aux applications).
  2. Créez au minimum, depuis les modèles : téléchargement massif par un utilisateur, activité depuis des adresses IP anonymes ou suspectes, partage de fichiers avec des domaines personnels, création de règles de transfert suspectes.
  3. Réglez la gouvernance (suspendre l'utilisateur, notifier) une fois les alertes jugées fiables.
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Portail Defender > Cloud Apps > Stratégies : au moins une stratégie active par catégorie utile.
  • MCAS-003 reste « non évaluable » dans AuditM365 (stratégies non exposées par l'API) : c'est attendu.

Documentation Microsoft : learn.microsoft.com/en-us/defender-cloud-apps/control-cloud-apps-with-policies · learn.microsoft.com/en-us/defender-cloud-apps/policies-overview

MCAS-004

Shadow IT : applications cloud non approuvées

Sévérité moyenne
Ce qui est vérifié
Aucune application cloud marquée « non approuvée » (unsanctioned) ne doit être utilisée dans l'organisation sans évaluation préalable.
Valeur attendue
Aucune application non approuvée en cours d'utilisation.

Temps estimé1 h, puis 1 à 2 semaines de collecte

RéférentielsANSSI Hygiène mesure 4RGPD Art.28RGPD Art.30

À savoir avant de commencer : Cloud Discovery a besoin de données : le plus simple est l'intégration Defender for Endpoint (postes intégrés, MDE-001), sans boîtier ni journaux de pare-feu. Marquer une application « non approuvée » la bloque sur les postes intégrés : prévenez les utilisateurs et proposez l'outil approuvé équivalent.

Corriger dans le portail

  1. Portail Microsoft Defender > Paramètres > Points de terminaison > Fonctionnalités avancées : activez « Microsoft Defender for Cloud Apps ».
  2. Paramètres > Cloud Apps > Microsoft Defender for Endpoint : cochez « Appliquer le blocage des applications ».
  3. Après 1 à 2 semaines : Cloud Apps > Cloud Discovery > tableau de bord : triez les applications par score de risque et par nombre d'utilisateurs.
  4. Applications à risque sans usage justifié : « Non approuvée » (bloquée sur les postes intégrés) ; outils validés : « Approuvée ».
Ouvrir la page dans le portail Microsoft ↗

Vérifier la correction

  • Portail Defender > Cloud Apps > Cloud Discovery : le tableau de bord affiche des applications découvertes.
  • Relancez un audit : MCAS-004 n'est plus « non évaluable ».

Documentation Microsoft : learn.microsoft.com/en-us/defender-cloud-apps/discovered-apps · learn.microsoft.com/en-us/defender-cloud-apps/governance-discovery
